## 二、加密判定：从「看真人行为」改成「字段特征」

用户明确要求：**不要等见到真人再判断，大厅就要能看出**。

### 为什么不能靠单一字段

- RC 的 `getFloat(actor+0x47C) == 40.0f` 实测在我们这版是 `enc=0/N`（从不为 40）
  → 那个偏移在我们版本不是加密标志。
- 我们一直在用的 `0x42C`（tf）实测 `t42=N/N`，**所有角色恒为 40**（那是"类型"字段）
  → 也不能当判据。

### 最终采用的判据：**多个真人的 Z 是否为同一平面**

```c
// 收集本帧所有真人的世界 Z
zmin, zmax, n
// 加密时游戏把所有真人映射到同一个假平面：
enc = (n >= 3 && (zmax - zmin) < 50.0f) ? 1 : 0;   // 50 单位 = 0.5m
// 真人不足 3 个时退回：|真人平均Z - 自己Z| > 3000 → 加密
```

**为什么这个能在大厅用**：
匹配大厅里通常就有其他玩家（实测 `pl=6~8`），够了 3 个就能判。
不需要进对局，也不需要等他们靠近——只要 Actor 在 cull 内。

**输出**：`enc3=1/0/-1`、`encz=`（诊断行，带 zmin/zmax/zspan/enz/aiz/localz/enN/aiN）

**绘制端左上角**：
```
坐标 加密中（红） / 坐标 正常（绿） / 坐标 未知（灰）
```
`-1` 只在"视野里真人不足 3 个且自己坐标不可用"时出现。

### 实测数据（2026-10-25 18:09，可能已解除加密）

```
zmin=-611 zmax=-441 zspan=170 enz=-531 aiz=359 localz=117 enN=6 aiN=23
enc3=0
```
6 个真人 Z 跨度 1.7m —— 属于正常范围（不同人脚下高度略有差异），判定未加密。
如果确实处于加密态，zspan 应该接近 0。
