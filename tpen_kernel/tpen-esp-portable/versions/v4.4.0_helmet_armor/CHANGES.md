# v4.4.0 — 头甲等级定位成功（0x1f80 / 0x1f90）

## 结论

```
头盔等级 = *(u32*)(actor + 0x1f80)
护甲等级 = *(u32*)(actor + 0x1f90)
```
范围 0 = 没穿，1~6 = 等级。

## 怎么定位的（用「自己」当对照）

RC 的链是 `actor+0x2188 → +0x1D8 → +0x30/+0xF0`，照抄过来全是无效值
（`am+0x1D8` 读出 0xffffffff）。

放弃照抄，改用**已知答案反查**：

1. 先确认 `actor+0x1b38 / +0x2008` 是 `BPC_CharacterArmorManager_C`（类名验证通过）。
2. 扫 ArmorManager 内部 0x0~0x600 的 u32，挑出所有落在 1~6 的：
   ```
   lv+38=2  lv+9c=1  lv+c0=3  lv+d8=1  lv+278=2  lv+27c=4
   lv+340=2 lv+40c=1 lv+4d4=2 lv+514=3  lv+5a0=1  lv+5a4=4
   ```
   太多候选，分不清。
3. **关键一步**：让用户报出「我自己是 3 头 3 甲」，然后扫**自己 actor 全身**
   0x0~0x2400 里所有 u32==3 的偏移：
   ```
   SELF3  670 850 8a0 c88 fe8 11c0 1290 1f80 1f90
   ```
   其中 `0x1290` 是已知的角色分类枚举（=3 表示真人），排除；
   剩下唯一**相邻成对**的就是 **0x1f80 / 0x1f90**（差 0x10）。
4. 验证：直接读自己 → `SELF_LA h=3 a=3` ✓
   再读场上 3 个真人 → 全部 `3 3` ✓

## 输出格式

`t=` 行第 9/10 字段就是 甲 / 头 等级，绘制端显示成：

```
卡特·维特 头3 甲3 51M
德文·林赛 头3 甲3 57M
人机 45M                 ← 人机没有装备数据，不显示头甲
```
