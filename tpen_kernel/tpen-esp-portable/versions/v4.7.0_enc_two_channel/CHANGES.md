# v4.7.0 — 加密状态判断：双通道（真人对比 + ACE 文件监控）

## 一、判据来自实测对比

| 指标 | 不加密态（实测） | 加密态（历史快照） |
|---|---|---|
| 真人平均 Z | 2685~2991 | -522 |
| 人机平均 Z | 2255~2701 | 516 |
| **dz（两者差）** | **291~414** | **1038** |
| **zspan（真人内部跨度）** | **808~1595** | **287** |

加密会同时造成两件事：
1. 真人整体偏离人机 Z（dz 变大）
2. 真人之间被压到同一平面（zspan 变小）

**双条件判据**（比单看 dz 稳，能排除"真人在不同楼层"的误判）：

```c
if (enN >= 3 && aiN >= 3)  enc4 = (dz > 500 && zspan < 600) ? 1 : 0;
else if (dz >= 0)          enc4 = (dz > 900) ? 1 : 0;   // 样本少时收紧
else                       enc4 = -1;
```

## 二、但这条通道需要真人在场

用户明确提出：**要在大厅 / 没有真人时也能确定加密状态**。

所以加了第二条通道：**监控腾讯 ACE 的工作目录**

```
/data/data/com.tencent.mf.uam/files/ano_tmp/   ← 37 个 .dat（ace_* / tss* / ano_*）
```

每 2 秒 `opendir + stat`，统计 5 秒内被写过的文件数，输出 `ace=N <文件名>`。

- **纯文件操作，不碰游戏内存**，不会增加被检测的风险
- **不需要真人在场**
- 原理假设：ACE 判定异常 → 写标记 → 游戏读标记 → 加密坐标
