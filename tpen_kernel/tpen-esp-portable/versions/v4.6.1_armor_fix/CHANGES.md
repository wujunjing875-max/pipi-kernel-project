# v4.6.1 — 护甲等级偏移修正（0x1f90 → 0x1f84）

## Bug

上一版头甲读的是 `actor+0x1f80`（头盔）和 `actor+0x1f90`（护甲）。

用户报「我 3 头 4 甲」，但程序读出来是 `h=3 a=3` —— **护甲读错了**。

## 为什么之前没发现

上次标定时用户是 **3 头 3 甲**，`1f80=3`、`1f90=3` 都是 3，
**两个候选值相同，根本无法区分哪个是头哪个是甲**，于是错的那个也"碰巧对了"。

## 定位

让用户换成 **3 头 4 甲**，扫自己 actor 里所有 `==3` 和 `==4` 的偏移：

```
S3 (值=3): ... 1f80  1f90
S4 (值=4): ... 1f84  1f94
```

直接读四个值：

```
1f80=3  1f84=4  1f90=3  1f94=4
```

**布局是 `[头][甲]` 重复两次**：组内相差 4，组间相差 0x10。
- `0x1f80` = 头盔，`0x1f84` = 护甲
- `0x1f90` = 头盔（拷贝），`0x1f94` = 护甲（拷贝）

## 修正

```c
int h9 = (int)r32(a + 0x1f80);   // 头盔
int v9 = (int)r32(a + 0x1f84);   // 护甲（原来是 0x1f90）
```

验证：自己读 `1f80=3 1f84=4` ✓

## 教训

**用「已知答案」标定偏移时，已知值必须能让候选偏移互相区分。**
3头3甲 这种"两个值相同"的情形，等于没有标定 —— 必须换一组不同的值再验一次。
