# 03 · 偏移表（最重要的一份）

> 所有偏移都是**实测逆向**出来的，不是猜的。
> 每条都标了**可信度**和**验证方法**，方便换游戏版本后重新校准。

---

## 一、可信度标记

| 标记 | 含义 |
|---|---|
| ✅ **实机验证** | 在真机上跑通、且和预期一致 |
| ⚠️ **部分验证** | 能读到合理值，但没在多种场景下验证过 |
| ❌ **已否定** | 试过，不对，别再用 |
| ❓ **未定位** | 还没找到 |

---

## 二、UE4 基础链

```c
G_WORLD = 0xFBEEE10;          // ✅ libUE4.so 基址 + 这个偏移 = GWorld

world     = r64(base + G_WORLD);
level     = r64(world + 0x30);        // ✅
actors    = r64(level + 0x98);        // ✅ Actor 数组（TArray<AActor*>）
actor_cnt = r32(level + 0xa0);        // ✅ 数组元素个数（实测 1200~1700）
```

**注意**：`actors` 必须**一次性批量读**（`rd(actors, buf, cnt*8)`），
用 `r64(actors + i*8)` 逐个读会全部失败——驱动的单次读对非对象地址有限制。

## 三、Actor（角色）偏移

以下 `actor` 指 `BP_UamCharacter_C` / `BP_UamAICharacter_C` 的对象地址。

### 3.1 位置与朝向

```c
root   = r64(actor + 0x158);          // ✅ RootComponent（USceneComponent*）
         rd(root + 0x154, xyz, 12);   // ✅ 世界坐标 FVector（3 个 float）
```

> 加密态下这个坐标是**假的**（所有真人被映射到同一平面），见 06。

### 3.2 分类判定

```c
ps = r64(actor + 0x330);              // ✅ PlayerState 指针
   ps != 0  → 真人玩家（队友/敌人）
   ps == 0  → 人机 / 人机玩家

ua = r32(actor + 0x1290);             // ✅ 分类枚举
   1 = 人机
   2 = 远端玩家模型（含真人 + 少数 AI）
   3 = 真人玩家（**注意：不是只有自己！**）
```

> ⚠️ **踩过的坑**：曾以为 `ua==3` 只有本地自己，用它排除自己，
> 结果把附近 85~90m 的真人一起排掉了（他们 ua 也是 3）。
> **排除自己只能用 `dm == 0`**（和本地 RootComponent 完全重合）。

### 3.3 骨骼

```c
mesh = r64(actor + 0x370);            // ✅ SkeletalMeshComponent
bones_data = r64(mesh + 0x700);       // ✅ 骨骼变换数组 Data
bones_cnt  = r32(mesh + 0x708);       // ✅ 骨骼数量（实测 109）

// 第 i 根骨骼：ptr = bones_data + i*0x30
//   +0x00 ~ +0x0F  FQuat  Rotation
//   +0x10 ~ +0x1B  FVector Translation  ← 局部坐标
//   +0x1C ~ +0x27  FVector Scale
```

骨骼索引表（`BSEG`，28 根身体的连线，画骨骼用）：

```c
static const int BSEG[28] = {
    15,82, 15,1, 15,53, 53,54, 54,87, 15,23, 23,24, 24,86,
    1,2, 2,4, 4,92, 1,7, 7,9, 9,94
};
```

> 骨骼点在世界坐标下的算法：把局部坐标用 Mesh 的 ComponentToWorld 变换 + 根偏移。
> 加密态下骨骼会全部挤成一坨（十几像素），因为 Mesh 变换也是假的。

### 3.4 手持武器 / 实例名

```c
// t= 行的第 8 个字段是「手持物/物品实例名」，不是固定偏移，
// 是从 actor 上扫出来的名字（见采集端 weapon_like() / item_inst()）
```

## 四、玩家信息（PlayerState）

```c
ps = r64(actor + 0x330);              // ✅ 必须是 BP_UamPlayerState_C

// 名字（FString，UTF16）
name_ptr = r64(ps + 0x440);           // ✅ 实机验证，读到「家阳朋友」「战神PCC」等
           备选 r64(ps + 0x450);      // ✅ 同一内容的另一份拷贝
           还有 +0x6f8 / +0x718      // ✅ 也是同一名字

// 读 46 字节 UTF16 转 UTF8，遇到 0 或控制字符停止
```

> ❌ **已否定**：RC 源码里的 `PlayerState + 0x470` 在**我们这版不是名字**
> （读出来是乱码 `Ⱔ蔳q`）。RC 是另一个游戏版本的偏移，不要照抄。

> 读名字时会顺带把空格替换成 `_`，避免破坏 esp.txt 的空格分隔格式。

## 五、装备（头甲）

### 5.1 头盔 ✅

```c
helmet_lv = r32(actor + 0x1f80);      // ✅ 1~6，0=没穿
拷贝      = r32(actor + 0x1f90);      // ✅ 和 0x1f80 同值（同一份数据的两处拷贝）
```

**验证记录**：用户穿 3 头 4 甲 时 `1f80=3`；换成 3 头 3 甲 时 `1f80=3`。

### 5.2 护甲 ❓ 尚未找到

```c
❌ r32(actor + 0x1f84)   // 恒为 4，与装备无关（曾经误当成护甲）
❌ r32(actor + 0x1f94)   // 同上，恒为 4
❌ r32(actor + 0x1f64)   // 恒为 4
❌ r32(actor + 0x1fac)   // 恒为 4
```

**为什么误判过**：用户先报「3 头 **4** 甲」，恰好 `1f84` 就是常量 4，看起来吻合；
后来换成「3 头 **3** 甲」，`1f84` 仍是 4，才暴露出它是常量。

> **教训**：用已知答案标定偏移时，**已知值必须能让候选偏移互相区分**。
> 两个候选值相同（都是 3）的标定等于没做。

### 5.3 ArmorManager（未打通）

```c
armor_mgr = r64(actor + 0x1b38);      // ✅ 类名确认 BPC_CharacterArmorManager_C
            r64(actor + 0x2008);      // ✅ 同一个对象
```

RC 的链是 `armMgr + 0x1D8 → +0x30(头盔) / +0xF0(护甲)`，但我们这版：

```c
❌ r64(armor_mgr + 0x1D8)   // 返回 0xffffffff（无效）
```

扫过 `armor_mgr + 0x0 ~ 0x500` 的所有指针，只发现类引用
（`BlueprintGeneratedClass`、`World`、`UADataTableManager`），**没有装备对象**。

**下一步方向**：远端玩家的装备数据可能客户端**根本不复制**（和 AI 一样），
只有本地玩家才有完整数据。需要再验证一次「别人穿 4 甲时，他 actor 上有没有 4 这个值」。

## 六、道具 / 容器

```c
// 分类靠类名关键词，不靠偏移：
kind = 2  容器   BOX_KW / CONT_KW（含 "Box" "Bag" "Case" "Safe" "DeathBox"…）
kind = 3  物资   ITEM_KW（含 "_Uam_C" "ItemBase" "_Item"）
```

### 6.1 物资必须带 `_Uam_C` ✅

```
地面可拾取：BP_9x19mm_PSO_gzh_Uam_C        ← 带 _Uam_C
装备本体  ：BP_Vest_Kirasa_C / BP_Helmet_SSh68_C   ← 不带，坐标不可靠
```

**规则**：`kind==3` 必须含 `_Uam_C` / `ItemBase` / `_Item` 才画。
否则会把「穿在身上的装备 actor」当成地上物资画出来（表现为悬空的头甲）。

### 6.2 穿在角色身上的装备要剔除 ✅

装备 actor 的 RootComponent 坐标 = 角色坐标，所以：
遍历时记录本帧角色世界坐标，物资若与任一角色距离 < 2m 就跳过。

## 七、视角矩阵（投影）

```c
// 相机管理器链（采集端自标定 + 固定偏移）
camMan = r64(pc + CAM_OFF);
matrix = r64(camMan + 0x???);        // 4x4 视图投影矩阵
```

投影公式（采集端已封装）：

```c
float w = q[0]*M[3] + q[1]*M[7] + q[2]*M[11] + M[15];
float sx = CX + (q[0]*M[0] + q[1]*M[4] + q[2]*M[8]  + M[12]) / w * CX;
float sy = CY - (q[0]*M[1] + q[1]*M[5] + q[2]*M[9]  + M[13]) / w * CY;
// w <= 1.0 表示在身后，要跳过
```

`CX=1207.0f, CY=540.0f` 是 2414x1080 屏幕的中点。

## 八、自标定项（运行时自动学）

| 项 | 方法 | 学到的值 |
|---|---|---|
| `CTRL_OFF` | 扫 `0x300~0x400`，找类名含 `PlayerController` 的指针 | `0x348` |
| `OFF_VEST` | 扫 `0x600~0x2200`，找类名含 `/LV` 的资产 | `0x8b8`（耐久曲线） |
| `GS_OFF` | 扫 `0x200~0x500`，找**元素类名含 PlayerState** 的 TArray | ❓ 未学到 |

> 自标定的好处：换游戏小版本时只要类名不变，偏移能自己重新学到。
> 坏处：如果扫不到（比如场景里没有该对象），就会一直是 0。

## 九、换游戏版本后的重新校准流程

1. **先验 GWorld**：`r64(base+0xFBEEE10)` 非空 → 链没变
2. **验 Actor 数组**：`cnt` 在 1000~2000 → 正常
3. **验 RootComponent**：`r64(actor+0x158)` 是有效指针、`+0x154` 读出的坐标量级合理 → 没变
4. **验 PlayerState**：`r64(actor+0x330)` 的类名是 `BP_UamPlayerState_C` → 没变
5. **验名字**：读 `ps+0x440` 出来是可读文字 → 没变
6. **验头甲**：拿自己的装备做对照（**必须用能区分开的值，比如 3头4甲**）

**校准工具**：`tools/uzi_dump.c` 可以把整个 actor 的 0x0~0x2400 全 dump 出来，
配合 `tools/diff_snapshot.py` 对比两份快照找差异字段。

> ⚠️ 但 dump 会大量读内存，**可能触发反作弊**（见 06），调研时用，平时不要跑。
